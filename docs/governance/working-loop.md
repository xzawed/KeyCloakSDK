# 작업 루프 — 무엇을 어떤 순서로 하고, 어디서 멈추는가

<!-- doc-status: living -->

> **이 문서는 순서다. 규칙이 아니다.** 무엇을 어기면 안 되는지는 [`CLAUDE.md`](../../CLAUDE.md)와
> `.claude/rules/<lang>.md`가 소유한다. 여기는 **어떤 순서로 밟고 어디서 "만들지 않는다"로 나가는가**만 적는다.
>
> ⚠️ 최근 커밋이 이 루프와 다르게 움직이면 **틀린 쪽은 커밋이 아니라 이 문서다.**

---

## 0. 어느 루프인가

| 지금 하는 일 | 밟을 절차 |
|---|---|
| 새 언어 SDK를 만든다 / 언어에 기능을 넣는다 | [AI 거버넌스 프레임워크 §7](ai-governance-framework.md) + [add-a-language playbook](../guides/add-a-language-playbook.md) |
| 불변식을 증명한다 · 가드를 들인다 · 문서를 고친다 · 하네스를 손본다 | **이 문서** |

아홉 언어가 이미 `main`에 있으므로 대부분 아래쪽이다.

## 1. 루프

```
0. 전제를 측정한다 ──── 아니오 / 이미 덮임 / 수렴 안 함 ──▶ ✗ 기각(되살릴 조건을 적고 끝낸다)
        │ 참
        ▼
1. 공허성 증명  "지금 가드가 이 자리를 못 본다"
        ▼
2. 실패하는 테스트 + 대조군  ◀───────┐
        ▼                            │ 3요건이 안 나오면
3. 최소 구현                          │ 설계로 되돌아간다
        ▼                            │
4. 커밋  ← 변이보다 앞                 │
        ▼                            │
5. 변이 3요건 (a)(b)(c) ─────────────┘
        ▼
6. 부류 재스캔  (지적받은 N은 불완전하다)
        ▼
7. 실행하고 출력을 다시 읽는다  (실행 ≠ 확인)
        ▼
8. 기록 (명령·수치·되살릴 조건)
```

둘이 핵심이고, 둘 다 **틀린 순서로 해 보고** 고친 것이다.

- **기각은 우회가 아니라 출구다.** 0단계에서 나가는 것이 정상 종료다.
- **커밋이 변이보다 앞이다.** 커밋 없이는 복원 후 `git diff` 빈 출력을 확인할 방법이 없다.

## 2. 단계

### 0. 전제를 측정한다

착수 근거가 되는 문장을 **명령으로** 확인한다. 계획서 문면·다른 세션의 메모·로컬 산출물은 전제가 아니다(git-ignored 스크래치를 CI 상태로 읽은 전례가 있다).

**끝나는 조건**: 근거 문장마다 그것을 낸 명령과 출력이 손에 있다. 없으면 그 문장을 쓰지 않는다.

### ✗ 기각 — 0단계에서 나가는 길

아래 일곱 중 하나라도 걸리면 만들지 않는다. 판정과 **되살릴 조건**을 기록하고 끝낸다.

1. **전제가 지금 트리에서 거짓인가?**
2. **이미 덮는 것이 있는가?** 드리프트 가능 자리를 **전수**로 뽑고 기존 가드가 그 전부를 보는지 확인한다.
3. **더 강한 것이 있는가?** 문서끼리의 자기일치보다 **SSOT 대조**가 강하다 — 자기일치는 둘 다 틀린 경우를 통과시킨다.
4. **불변식이 선언돼 있는가?** 값이 우연히 같은 것과 선언된 불변식은 다르다. 선언이 없으면 가드가 정책을 새로 만드는 셈이고 그건 사람의 몫이다.
5. **새 장치가 수렴하는가?** 참/거짓이 **문맥**에 달렸으면 정규식은 수렴하지 않는다.
6. **실패 표면이 주는가, 느는가?** "탐지됨 → 표현 불가능" 치환이 새 실패 모드를 낳으면 순이득이 아니다.
7. **격리가 단언을 대신하는가?** 답은 **아니오**다. 구조적 격리 위에 출처 단언을 얹는다.

기각에는 **되살릴 조건**을 함께 적는다. 없으면 기각은 판단이 아니라 회피다.
**이미 기각된 제안은 되살릴 조건이 오기 전에 다시 만들지 않는다.**

| 기각 | 한 줄 | 되살릴 조건 |
|---|---|---|
| 금칙 문구 린트 | 히트가 설명·캐비앳·주장이 섞여 정규식이 수렴하지 않음 | 문맥 없이 참/거짓이 갈리는 금칙이 실측될 때 |
| 문서 내부 수치 자기일치 | 게시 개수는 `DF_PUBLISHED`가 덮고, 자기일치는 둘 다 틀린 경우를 통과 | SSOT 없는 수치가 여러 문서에 흩어져 드리프트가 실측될 때 |
| 퀵스타트 「중복」 삭제 | README 펜스가 가드 조준점이고 레지스트리 페이지엔 getting-started가 없음 | 두 예제가 실제로 갈릴 때. 그때도 삭제가 아니라 한쪽 생성·한쪽 파생 |
| pre-1.0 문단 통합 | 8개는 동일하나 Rust는 Cargo 캐럿 고유 사실을 담음 | 세 번째 자리까지 번져 손으로 맞추기 시작할 때 |
| 게차 그룹화 | 태그 라우팅이 이미 있고 Java·Python은 순손실 | 스텁 계약을 스펙 개정으로 바꾼 뒤 순손실 그룹이 사라졌을 때 |
| CLAUDE.md 생성물화 | 마커 비용이 이득을 넘고, 매니페스트 파생은 doc-facts를 자기대조로 만듦 | doc-guard 사실이 매니페스트 **바깥** 원천으로 옮겨질 때 |

### 1. 공허성을 먼저 증명한다

**지금 가드가 이 자리를 못 본다**를 보인다. `grep -rln '<겨눌 것>' scripts/ .github/workflows/` 한 줄이면 되고, 히트가 0이어야 존재 이유가 있다.

> 확정 결함의 대부분은 "아무도 안 본 자리"가 아니라 **"가드가 있는데 그 자리를 안 겨눈" 자리**였다. 그래서 기본 수는 신규 가드가 아니라 **기존 가드의 조준점 확대**다.

### 2. 실패하는 테스트 — 그리고 대조군

빨간 것을 눈으로 본 뒤에 구현한다. **대조군**을 같이 만든다: 검사 대상을 껐을 때 **통과해야 하는** 케이스.

> 대조군이 없으면 조용히 공허해진다 — 라이브러리 기본값이 우리 설정과 같으면 하드닝을 지워도 초록이 되고, 순서 의존 버그는 기본 순서에서 보이지 않는다.

### 3. 최소 구현 → 4. 커밋 (변이보다 앞)

파괴적 명령 전에 트리를 깨끗하게 만든다. 복원은 `git checkout`도 백업 파일도 아닌 **역연산**이고, 복원 후 `git diff`가 **빈 출력**임을 확인하기 전에 다음으로 가지 않는다.
**변이는 리포가 아니라 복사 트리에서 하는 편이 안전하다**(원본을 만지지 않으면 복원 자체가 없다).

### 5. 변이 3요건 — 그리고 되돌아가기

셋을 **함께** 보고한다. 하나라도 안 나오면 2단계로 돌아간다.

| | 무엇을 답하는가 | 없으면 |
|---|---|---|
| **(a) 변이 → 실패** | 이 가드가 *무언가*를 겨누는가 | 아무것도 안 겨눌 수 있다 |
| **(b) 복원 → 통과 + `git diff` 빈 출력** | 그 실패가 *변이* 때문인가, 트리를 부순 탓인가 | "빨개졌다"만 남고 원인을 모른다 |
| **(c) 가드 OFF + 같은 변이 → 통과 (N>0)** | 그 실패가 *이 가드*의 몫인가 | 다른 어서션·캐시·라이브러리 기본값이 대신 잡아 준다 |

⚠️ **(c)의 형식**은 "가드 OFF + 건강한 트리 → 전부 통과"가 **아니다**(그건 트리가 건강하다는 말일 뿐이다). `가드 ON + 변이 = 실패`와 `가드 OFF + 같은 변이 = 통과`를 나란히 찍는다.

⚠️ **변이는 자기가 고르지 않는다.** 자기 어서션이 잡도록 고른 변이는 순환이라 3요건을 "하고도" 공허할 수 있다 — **"이 코드·문서가 현실적으로 낡는 방식"** 에서 유도한다.

⚠️ **하드닝을 우리가 끌 수 없으면**(라이브러리에 박힌 동작 등) 대조군이 (a)를 대리한다.

### 6. 부류 재스캔

지적받은 N건을 고친 뒤 **같은 부류를 리포 전체에서 다시 스캔**하고 스캔 명령과 히트 수를 커밋에 적는다. 재스캔 없이 "전부"·"무손실"·"정확히 하나"를 쓰지 않는다.

### 7. 실행하고 출력을 다시 읽는다

종료코드가 아니라 **출력**을 읽는다. 파이프를 태우면 exit code가 가려진다. "명령이 실행됐다"에서 "결과가 의도와 같다"로 건너뛰는 것이 이 저장소 실수의 단일 뿌리다.

### 8. 기록

**커밋 메시지에**: 수치마다 그것을 낸 명령 · 3요건 측정표 · 재스캔 명령과 히트 수 · 기각이면 판정 + 되살릴 조건.
**문서에**: 완료된 사실만. 되살릴 조건과 근거는 여기(기각 표)에.

### ⚖️ `CLAUDE.md`를 늘리는 PR

`CLAUDE.md`에는 **목표 바이트 수가 없다.** 남은 것은 `doc-budget` 래칫뿐이고 상한이 올라가는 조건은 하나다:

> **증가분이 기계 검증을 사 와야 한다.** 그 증가가 `check-docs`의 facts/anchors를 함께 늘리는 것을 보이고 `--min-facts`/`--min-anchors`를 **같은 커밋에서** 올린다. 교환이 없으면 상한은 내려가기만 한다.

**교환이 아닌 것**: 산문 추가·설명 보강·이력 서술. 줄이거나 **블록 HTML 주석**으로 남긴다(주입되지 않아 계상되지 않는다).

## 3. 무엇을 "완료"라 부르는가

- [ ] 0단계 전제가 명령으로 확인됐다 (또는 기각 판정 + 되살릴 조건이 적혔다)
- [ ] 실행 결과를 **다시 읽었다** — 종료코드가 아니라 출력을
- [ ] 새 가드라면 3요건 (a)(b)(c)가 측정표로 있다
- [ ] 같은 부류를 리포 전체에서 재스캔했고 명령·히트 수가 커밋에 있다
- [ ] 트리가 clean이고 `git log`·`git status`로 확인했다

## 4. 이 문서가 썩는 방식

1. **현재 수치를 본문에 박는다.** 어서션 수·게시 개수는 매 커밋 변한다 — 루프와 형식만 두고, 수치가 필요하면 **그것을 내는 명령**을 적는다.
2. **자기보고를 사실로 적는다.** 이 문서의 "우리는 이렇게 한다"도 커밋과 안 맞으면 **문서가 틀린 쪽**이다.
3. **계획서가 된다.** 날짜 찍힌 체크박스가 들어오는 순간 미체크 항목의 운명을 따른다 — 진행 상태는 계획서가 소유한다.
4. **추론을 절차로 고정한다.** 근거 없이 "이렇게 하면 안전하다"를 적으면 규칙 카탈로그가 된다.
5. **상주하지 않으면 없는 것과 같다.** `CLAUDE.md`가 이 문서를 가리키는 한 줄이 생명선이다.
6. **가드로 이 문서의 문장을 집행하려 든다.** 하지 않는다 — 순서의 참/거짓은 문맥이다. 기계가 지키는 것은 지도 등록과 `doc-status` 정합뿐이다.

---

> **만들기 전에 전제를 재라.** 이미 덮이거나, 수렴하지 않거나, 불변식이 선언돼 있지 않으면 만들지 말고
> 되살릴 조건만 남겨라. 만들기로 했으면 실패하는 테스트와 **대조군**을 먼저 두고, 통과한 뒤에 **커밋하고**,
> 그다음에야 변이하라. 변이는 자기 어서션이 아니라 **실제로 낡는 방식**에서 고르고, 3요건이 안 나오면
> 구현으로 돌아가라. 지적받은 N을 고쳤으면 **부류를 다시 스캔하라.** 명령을 실행한 다음 **출력을 다시 읽어라.**
> — 추론은 검증이 아니고, 실행은 확인이 아니다.
