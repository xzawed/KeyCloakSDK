# AI 거버넌스 · 이중검증 · 루프 엔지니어링

**적용 대상**: 언어 SDK 구현(새 언어 추가·언어에 기능 넣기). 그 밖의 작업 — 가드·문서·하네스 — 은 [작업 루프](working-loop.md)를 탄다. 6단계 순서 자체는 [add-a-language playbook](../guides/add-a-language-playbook.md)이 소유한다.

## 1. 역할 (직무 분리 + 모델 독립성)

| 주체 | 권한·책임 |
|---|---|
| **사람** | 최종 책임 — 계획 충돌 재정, 게이트 오버라이드, **머지·배포 최종 승인** |
| **Claude 컨트롤러** | 태스크 디스패치, 리뷰 재정, 감사 기록 |
| **Claude 구현 에이전트** | TDD 구현(태스크별 신규), 자체 리뷰 |
| **Claude 리뷰 에이전트** | 스펙 준수·코드 품질 판정(태스크별 신규) |
| **Codex 독립검증자** | 모델-독립 교차검증(G5), RCA 공동 진단 |

**구현자 ≠ 리뷰어 ≠ 검증자.** 검증자는 **다른 모델**이다 — 같은 모델의 상관된 맹점을 상쇄한다. 자기 코드 자기 승인 금지.

## 2. 정량 품질 게이트 (태스크마다 전부)

| 게이트 | 지표 | 임계값 |
|---|---|---|
| **G1 빌드** | 컴파일 에러 | 0 |
| **G2 단위테스트** | 통과율 | 100% |
| **G3 커버리지** | 라인 / 브랜치 | **≥ 90% / ≥ 85%** |
| **G4 스펙 준수** | 미해결 Critical/Important | 0 |
| **G5 Codex 교차검증** | 미해결 불일치 | 0 |
| **G6 보안** | 토큰·시크릿 로그, 내부 타입 누출 | 0 |

⚠️ **G1–G3의 측정 수단은 언어마다 다르다** — 여기에 특정 언어의 명령을 박지 않는다. 실제 명령은 루트 `CLAUDE.md`의 툴체인 표와 `.claude/rules/<lang>.md`가 소유하고, 커버리지 게이트 설정은 `scripts/check-coverage.mjs`가 기계 대조한다.

**G3 대상**: 로직 모듈(config·tokens·PKCE·metadata·JWT 검증·TokenProvider·admin 리소스 파사드·예외 변환). **라이브 네트워크 경계**와 통합 전용 코드는 커버리지 도구의 exclude로 빼고 **통합테스트로 검증**한다.

## 3. 루프 엔지니어링 (지표 미달 시)

```
[측정] → 임계값 비교
  ≥ → PASS → 다음 게이트
  < → ① RCA(Claude + Codex 공동 진단) → ② 최소 시정 → ③ G1~G6 재실행 → ④ 재측정
      게이트당 최대 3회 → 초과 시 사람에게 에스컬레이션
```

모든 반복은 **이전 지표 → 조치 → 이후 지표 → RCA 요약**으로 기록한다.

## 4. 감사 추적

- **게이트 이력**은 PR·커밋 메시지에 남긴다 — 별도 검증 로그 파일은 새 언어의 필수 산출물이 **아니다**.
- **진척 원장**은 `.superpowers/sdd/<계획>/progress.md`(gitignore, 컴팩션 복구용). ⚠️ **git-ignored 로컬 산출물을 CI·저장소 상태로 읽지 않는다**(`git check-ignore -v` 한 번이면 갈린다).
- **재현성**: 의존성 버전은 언어별 매니페스트가 SSOT(루트 `CLAUDE.md`가 표로 요약하고 `check-docs.mjs`가 대조한다 — 여기에 복제하지 않는다), Keycloak 컨테이너 태그 고정, 툴체인은 `.claude/rules/<lang>.md`.

## 5. 거버넌스 통제

- **브랜치 격리** — `main`에 직접 커밋하지 않는다. 관례가 아니라 **서버 상태**다(룰셋 `PRIMARY`가 `bypass_actors: []`로 소유자에게도 예외를 주지 않는다). 브랜치는 `fix/`·`docs/`·`chore/`·`feat/` 접두를 쓰고 **머지 후 지운다**(확인: `git ls-remote --heads origin` — `main`만 남아야 한다). 머지는 squash, 승인은 사람.
  > ⚠️ **규칙을 적을 때는 그것이 무엇으로 확인되는가를 함께 적는다.** 이 항목은 한때 오래전에 사라진 브랜치 이름을 규칙으로 가리키고 있었다.
- **되돌릴 수 없는 작업은 사람 승인 필수** — 레지스트리 배포는 에이전트 자동 실행 금지. 서명키·토큰은 CI 시크릿으로만.
- **비밀 취급** — 코드·로그·커밋에 토큰/시크릿 금지(마스킹 유틸 + 리뷰로 강제).
- **최소권한 모델 선택** — 역할별 최저 적정 모델.
- **에스컬레이션 의무** — 서브에이전트 BLOCKED·계획 모순·게이트 3회 초과는 무시하지 않고 사람에게 보고한다.
- **커밋은 `git add -A && git commit`** — `git commit -am`은 untracked를 스테이징하지 못해 신규 파일이 누락된다.

⚠️ **구체적인 경로·버전을 이 문서에 적지 않는다.** 예전에는 특정 PC 경로와 JDK 패치 버전을 본문에 박아 두고 바로 아래 줄에서 "커밋하지 않는다"고 적는 자기모순이었고, 실제로 낡았다. 새 머신이라면 `node scripts/doctor.mjs [<lang>…]`.

## 6. 태스크 실행 순서

1. **디스패치** — 태스크 브리프만 담아 구현 서브에이전트에 넘긴다(모델은 복잡도에 맞춘다).
2. **구현** — TDD(실패 테스트 → 구현 → 통과 → 커밋) + 자체 리뷰.
3. **G1–G3 측정** → 4. **G4 리뷰** → 5. **G5 Codex 교차검증** → 6. **G6 보안**.
7. **판정** — 전 게이트 PASS면 PR에 게이트 이력을 남기고 완료. 미달이면 §3 루프.
8. **다음 태스크** — 사이에 사람 확인 없이 연속 실행하되, BLOCKED·모순·3회 초과에서만 멈춘다.

Phase 완료 시 Phase 게이트(전 태스크 green + 통합테스트), 전체 완료 시 Codex 포함 최종 리뷰 → PR(사람 승인).
