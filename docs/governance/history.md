CI `install-all` 잡(야간 03:00 UTC + `workflow_dispatch`·`timeout-minutes: 90`·`INSTALL-MATRIX.md`+`signals/` 아티팩트, PR/푸시엔 미실행). **9번째 Kotlin 편입(PR #26)**: `publish/kotlin.sh`(SDK→nginx 정적 .m2 `mvn-repo-kotlin`) + 소비자 Gradle 프로젝트 `consume/kotlin-app`(게시 패키지 소비 — apps/kotlin과 SDK 의존소스만 다름) + `kotlin-run.sh`(install=gradle classes→quickstart→boot installDist) — end-to-end GREEN(26/26·9/9). install-net 실인터넷이라 SDK만 로컬 레지스트리·전이 deps는 Central(java 동형). **follow-up 해소(PR #28)**: (1) **rust install 이중컴파일 제거** — publish의 `cargo package`에 `--no-verify`를 붙여 verify 빌드(SDK 전체 15~25분 재컴파일)를 생략한다. .crate tarball은 그대로 생성되고(4단계가 복사·index 주입) SDK 실제 컴파일·검증은 consume(`cargo build --offline`)가 어차피 수행하므로 verify 빌드는 중복이었다 — publish 패키징 **15~25분→3.5초**(`install-verify.sh rust` 26/26·9/9 무회귀). (2) **루트 `.gitattributes`(`*.sh`·gradlew `eol=lf`)** — 리포에 루트 `.gitattributes`가 없어 `core.autocrlf=true`(Windows 흔한 기본값) 기여자는 LF로 커밋된 셸 스크립트 blob을 워킹트리에 **CRLF로** 받는다. `docker COPY`가 그 CRLF를 이미지로 옮기면 busybox `sh /app/run.sh`가 첫 `set -u`를 `set: illegal option -`로 거부하며(끝의 `\r`가 옵션으로 파싱) consume 엔트리포인트가 실제 작업 전 크래시한다(로컬 install-verify가 이 문제로 막혔던 것을 규명). `eol=lf`는 `core.autocrlf`를 오버라이드 — blob은 원래 LF라 CI 무영향, Windows 로컬 개발자 보호.
