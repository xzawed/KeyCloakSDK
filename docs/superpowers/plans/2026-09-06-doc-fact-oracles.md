# 문서 사실에 오라클 붙이기 — 배치 3 잔여 40건

**이 문서가 답하는 것 하나** — 「배치 3 감사가 남긴 40건을 **무엇을 먼저 세우고** 어떤 순서로 닫는가, 그리고 각 사실에 대해 **다시 깨지면 CI 가 어떻게 잡는가**.」

열린 항목의 소유자는 [잔여작업 등록부](remaining-work.md)의 `doc-audit-batch3-fixes-outstanding` 이다. 이 문서는 **그 항목 하나를 닫는 방법**만 소유하고, 다 닫히면 `doc-status` 를 `complete` 로 내리고 지도 §3 에서 지운다.

⚠️ **초안은 여섯 판정 중 넷이 틀렸다.** 독립 검토 레그가 뒤집었고 전부 명령 출력으로 확인했다 — 아래 ② 의 「초안이 틀린 자리」 열이 그 기록이다. **자기 계획을 자기가 승인하지 않는다**([작업 프로세스](../../governance/process.md) 역할).

## ⑤ TDD 규약 — 이 저장소에서 문서 작업의 red-green

1. **가드가 붙는 사실**(I1·I2·I6): 가드를 먼저 쓰고 **현재 트리에서 실패하는 것을 눈으로 확인**한 뒤 문서를 고쳐 초록으로 만든다. **3요건**을 남긴다 — (a) 변이→실패 (b) 복원→통과 (c) **구 스크립트+같은 변이→통과**(원인 확정). **공허 방지 하한**을 함께 둔다.
2. **가드가 안 붙는 사실**: **인용 게이트 역검증** — 감사가 인용한 옛 문자열이 그 줄에서 사라졌는지 기계로 본다(이번 세션 실측 16/20 · 10/10).
3. **계측기를 먼저 잰다.** ⚠️ 이번 세션에 손으로 짠 계측기가 **세 번** 고장났다 — `***` 리터럴 grep 이 마스킹 헬퍼를 쓰는 다섯 언어를 놓쳤고, 타입 선언 grep 이 별칭에 걸렸고, 변이 프로브의 `sed` 개행 이스케이프가 깨져 **잡히는 변이를 「침묵」으로 보고했다**(신뢰할 수 있는 도구로 다시 재니 fail-closed 였다).

### W1–W2 에서 실제로 밟은 것 둘 (다음 세션이 같은 값을 치르지 않도록)

⚠️ **「커밋이 변이보다 앞」을 어겨 W1 을 통째로 잃었다.** 가드 구현·앵커 4개·임계값 6곳을 **커밋하지 않은 채** 변이 프로브를 돌렸고, 프로브의 복원 단계 `git checkout -- .` 가 그것을 전부 되돌렸다. 되돌린 것은 변이만이 아니다 — **작업 트리 전체**다. 변이 프로브는 반드시 커밋 뒤에 돌린다.

⚠️ **공허 하한을 코드 상수로 박으면 required 체크가 저장소를 잠근다.** `COUNT_ANCHOR_MIN` 을 상수로 두자 앵커가 0개인 자가테스트 픽스처가 전부 빨개져 `153 passed / 75 failed` 가 됐다. `doc-facts` 는 required 이고 룰셋은 `bypass_actors: []` 라, 그대로 나갔으면 **모든 PR 이 막혔다**. 기존 min 플래그 넷과 같이 **CLI 플래그(기본 0)** 로 빼는 것이 이 저장소의 관용이다.

### 3요건 (c) 는 새 앵커 종류에는 그대로 적용되지 않는다

「구 스크립트 + 같은 변이 → 통과」는 **문법이 이미 있는 규칙**을 전제한다. `kind=count` 는 새 종류라 구 스크립트에는 그 문법이 없고, 구 스크립트는 앵커를 `kind=dep` 로 읽어 「앵커 뒤에 표가 없다」로 실패한다 — **다른 이유로 실패**하므로 인과가 확정되지 않는다(실측: 구 스크립트 + 같은 테스트 = 224 passed / 7 failed, 그 7 은 전부 `assert_ok` 쪽이다).

대신 **더 강한 형태로 확정했다**: 결함이 살아 있던 실제 트리(`8d5f008` — `docs/README.md` 1곳 · `rejected.md` 2곳이 「체크리스트 7」, 원천 §3 은 8)에서 **구 가드를 CI 와 똑같은 인자로 돌려 초록**임을 보였다. 새 규칙이 원인임을 그것이 증명한다.

## 역할 — Grok 독립 레그를 어디에 쓰는가

이번 세션 실측: **탐색보다 반박이 회수율이 높았다.** 문서 5개 묶음 탐색은 540초에 두 번 다 타임아웃했고, 주장 3건 묶음 반박은 전부 완주하며 배치 3 에서 **범위 정정 5건**을, 이 계획서에서 **판정 4건 뒤집기**를 냈다.

- **③ 검토**: 판정 자체를 반증(완료 — 초안의 I1 수렴성·I2 오라클 범위·I4 수렴성·I6 기각을 전부 뒤집었다).
- **⑤ 수행**: 각 가드의 **탐지 표면**을 반증(「이 변이를 놓치지 않는가」).
- **⑥ 검증**: 최종 반박. **어느 레그도 액면가로 받지 않는다** — 이번에도 Grok 의 주장 셋을 내가 직접 확인한 뒤에 반영했다.

⚠️ **범위를 3건 이하로 쪼갠다**(함정 (f)). 타임아웃하면 `grok_build_verify` 가 아니라 `grok_build_delegate` 로 간다.
