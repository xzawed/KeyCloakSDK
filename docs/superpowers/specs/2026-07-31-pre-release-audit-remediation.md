## 1. 문제

첫 공개 배포 직전 감사에서 나온 결함 중, PR #115가 다루지 않은 잔여분을 해소한다. PR #115는 **증명되지 않던 JWT 불변식**(9언어)·**Nimbus 예외 누출**(Java·Kotlin)·**JWKS 기본값 발산**·**릴리스 게이트 3종**을 처리했다. 이 스펙은 그 다음 층이다.

잔여 결함은 세 부류다.

| 부류 | 무엇이 문제인가 | 왜 지금인가 |
|---|---|---|
| A. 공격 프로브 공백 | 일부 언어에만 있는 공격 테스트가 있어, "아홉 언어가 동형으로 하드닝됐다"는 주장이 언어마다 다른 강도로만 참이다 | 게시 후에는 "이 언어는 그 공격을 테스트하지 않았다"를 사후에 발견하게 된다 |
| B. 관측 가능한 발산 | 리다이렉트(SSRF) 정책·admin CRUD 표면이 언어마다 다르다 | 두 SDK를 쓰는 소비자가 즉시 체감한다. 게시 후 바꾸면 파괴적 변경 |
| C. 버전 SSOT 취약 | 버전이 여러 파일에 흩어져 있거나(Java 7 POM) 이중 진실원천이다(dotnet) | 첫 릴리스에서 버전이 반쯤 적용되면 태워버린 좌표를 되돌릴 수 없다 |

## 3. 설계 결정

### 3-1. 공격 프로브는 "동형 최소집합"을 정의하고 그것을 전 언어에 강제한다

지금까지 프로브는 언어별로 그때그때 추가돼 집합이 달랐다. **동형 최소집합**을 명시한다:

1. `alg=none`(미서명) 거부
2. HS/RS 혼동(공개키를 HMAC 비밀로) 거부
3. 미해결 kid 거부 + 재조회 rate-limit
4. **위조 서명은 JWKS 재조회를 유발하지 않는다**(서명위조 DoS 증폭 차단)
5. 기형 JWKS(base64url 아닌 modulus 등)가 **깨끗한 SDK 타입 오류**로 나온다(panic/raw 예외 아님)
6. 클록 스큐 경계(안 통과 / 밖 거부)

> ⚠️ **비-목표**: 프로브를 "전부 같은 이름"으로 통일하지 않는다. 각 언어의 테스트 명명 관용을 따른다 — 이름이 아니라 **불변식**이 동형이어야 한다.

### 3-2. 리다이렉트 정책은 "명시적 차단"으로 통일한다

SSRF 하드닝은 기본값에 의존하면 안 된다. 하위 라이브러리가 기본으로 추종하지 않더라도, **버전 업그레이드로 기본값이 바뀌면 조용히 취약해진다**. 아홉 언어 전부 리다이렉트를 명시적으로 차단하고, 그 사실을 테스트로 고정한다.

> ⚠️ **결정**: OIDC authorization code 흐름의 `redirect_uri`는 이것과 무관하다(브라우저 front-channel). 여기서 말하는 것은 **SDK가 만드는 back-channel HTTP 요청**(token·introspect·logout·JWKS·admin REST)이다.

### 3-3. admin `update()` 부재는 **문서화**로 해소한다(구현 아님)

Go·Rust에 `update()`가 없는 것은 하위 라이브러리 표면의 차이다. 첫 릴리스 직전에 admin API를 넓히는 것은 위험 대비 이득이 낮다 — 대신 [getting-started.md](../../guides/getting-started.md)에 **언어별 admin 능력 매트릭스**를 두어 소비자가 기대를 정확히 갖게 한다.

> ⚠️ 이 결정은 README가 "개념·계층이 동형"이라고 말하는 것과 충돌하지 않는다. 동형인 것은 **계층과 흐름**이지 메서드 전수가 아니며, §4(b) 문서화된 은닉성 예외가 이미 같은 성격의 차이를 다루고 있다.

### 3-4. 버전 SSOT는 "가드"로 해소한다(구조 변경 아님)

Java를 `${revision}`으로 바꾸거나 dotnet의 csproj 버전을 제거하는 것은 릴리스 직전에 하기엔 파급이 크다. 대신 **어긋남을 검출하는 가드**를 둔다 — `scripts/check-docs.mjs`가 이미 하는 일과 같은 성격이다.
